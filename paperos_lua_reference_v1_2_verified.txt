PaperOS v1.2 — Lua API Reference (verified against lua_app.h source)
=====================================================================
Board: ESP32-S3FN8 — NO PSRAM (N8 = flash only, no R suffix). os.psram()
always returns 0, this is correct, not a bug[cite: 2].

MEMORY MODEL — READ THIS FIRST
-------------------------------
- os.heap()   -> ESP.getFreeHeap(): whole-board free SRAM[cite: 2].
- os.luamem() -> used, limit: Lua's OWN sandboxed heap via a custom
  allocator, hard-capped at LUA_HEAP_LIMIT_BYTES = 96 * 1024 (98304)[cite: 2].
  This is a SEPARATE budget carved out of the same physical SRAM as
  os.heap()[cite: 2]. Going over it raises a normal Lua "not enough memory" error
  -- IF the failure is caught cleanly[cite: 2]. See BUG-1 below: it isn't always[cite: 2].
- With SD mounted, board free heap drops by ~27KB immediately (FAT/sector
  buffers), before writing anything[cite: 2]. Confirmed by measurement[cite: 2].
- Full-screen canvas (240x135 RGB565 double buffer) permanently reserves
  ~63KB of SRAM whenever a graphical app (incl. the Lua terminal) is open[cite: 2].
- No PSRAM means total real headroom for scripts can be as low as
  30-60KB free board heap during normal SD + display use[cite: 2]. Budget scripts
  accordingly -- this is a small-memory device, not a typical Lua host[cite: 2].
- NOTE: Due to extreme SRAM constraints (no PSRAM), TLS/HTTPS handshakes
  will fail due to Out-Of-Memory. Use plain HTTP only for net.get / net.post.
- RULE OF THUMB: any loop doing 50+ allocations (string concat, table
  creation, json.encode/decode, etc.) should call collectgarbage()
  every ~30-50 iterations[cite: 2]. Confirmed empirically to prevent BUG-1 below[cite: 2].

KNOWN BUGS (confirmed against source / on-device testing)
-----------------------------------------------------------
BUG-1 [confirmed, reproducible]: json.encode()/json.decode() can SILENTLY
  return corrupted data instead of erroring when the board is under heap
  pressure (encoder uses Arduino String += with no malloc-failure check)[cite: 2].
  Reproduced: 250-500 iterations of json.encode+decode in a tight loop
  with no collectgarbage() -> wrong field value returned, no exception[cite: 2].
  Confirmed fixed by calling collectgarbage() every 50 iterations[cite: 2].
  Root cause is in Arduino String's OOM handling, not Lua itself, but
  json.decode()/_json_encode_table() should validate output rather than
  trust String didn't silently truncate[cite: 2].
  WORKAROUND (safe today): call collectgarbage() every ~30-50 json calls
  in any loop, especially with SD mounted and heap already low[cite: 2].

BUG-2 [confirmed]: os.gc() returns ESP.getFreeHeap() (whole-board heap),
  NOT Lua memory usage[cite: 2]. Name is misleading -- use os.luamem() for actual
  Lua heap usage[cite: 2].

BUG-3 [confirmed]: disp.rgb(r,g,b) returns 0 if called with no active
  canvas (g_lcanvas == nullptr), even though the RGB565 conversion itself
  doesn't depend on a canvas being open[cite: 2]. Only call disp.rgb() from a
  context where a graphical app/canvas is active[cite: 2].

BUG-4 [confirmed]: fs.mkdir(path) returns false both when the directory
  already exists AND on a genuine I/O error -- can't tell them apart from
  the return value alone[cite: 2]. Check fs.exists(path) first if you need to know
  which case you're in[cite: 2].

BUG-5 [confirmed]: json.decode() raises a hard Lua error (luaL_error) on
  invalid JSON instead of returning nil+message[cite: 2]. Always wrap in pcall():
    local ok, result = pcall(json.decode, str)[cite: 2]

BUG-6 [confirmed]: run(path) swallows script errors (prints to terminal,
  execution just stops) while dofile(path) propagates them via lua_error[cite: 2].
  A missing file is silent with run() but errors with dofile()[cite: 2]. Don't mix
  them up expecting the same error-handling behavior[cite: 2].

BUG-7 [by design, documented in source]: require(name) caches the loaded
  module PERMANENTLY for the life of the Lua session (registry table
  PAPEROS_REQUIRE_CACHE)[cite: 2]. Editing a .lua file on SD and calling require()
  again returns the OLD cached table[cite: 2]. No reload()/package.loaded[x]=nil
  exists[cite: 2]. To force a reload, use dofile() instead of require(), or
  reboot the device[cite: 2].

QUIRK: fs.ls(path) returns NOTHING (0 values) unless called with a
  second argument = true: fs.ls("/sd", true) returns a table of
  {name=, dir=, size=} entries[cite: 2]. fs.ls("/sd") alone only prints to the
  on-screen terminal and returns nothing -- don't call type() on it
  directly[cite: 2].

QUIRK: sound.play() and net.scan() block the Lua thread while running
  (up to their timeout), though both are interruptible via Ctrl+C
  (g_exec.interrupt)[cite: 2]. Don't call from inside a tight loop() callback
  expecting non-blocking behavior[cite: 2].

QUIRK: SD file access can intermittently report "file not found" on the
  very first run() immediately after copying a new file onto the card
  (observed on-device)[cite: 2]. If a freshly-copied script fails to run once,
  retry -- it typically works the 2nd time[cite: 2]. Root cause is unconfirmed
  (likely FS not fully flushed after card-reader/USB transfer)[cite: 2].

=====================================================================
os.*
=====================================================================
os.clock()                 -> number, seconds since boot (millis()/1000)[cite: 2]
os.time()                  -> number, seconds since boot[cite: 2]
os.millis()                -> number[cite: 2]
os.micros()                -> number[cite: 2]
os.heap()                  -> number, ESP.getFreeHeap() [see BUG-2][cite: 2]
os.psram()                 -> number, always 0 on this board (no PSRAM)[cite: 2]
os.luamem()                -> used, limit  (limit is fixed 98304)[cite: 2]
os.gc()                    -> number [see BUG-2: NOT lua mem][cite: 2]
os.cpu()                   -> number, CPU freq MHz[cite: 2]
os.flash()                 -> number, flash chip size bytes[cite: 2]
os.sketchsize()            -> number, current sketch size bytes[cite: 2]
os.core()                  -> number, FreeRTOS core id running this code[cite: 2]
os.date()                  -> string[cite: 2]
os.difftime(t2,t1)         -> number (t2-t1)[cite: 2]
os.remove(path)            -> true | nil,"remove failed"[cite: 2]
os.rename(a,b)              -> true | nil,"rename failed"[cite: 2]
os.apps()                  -> table, list of installed apps[cite: 2]
os.getenv(name)            -> always nil (stub)[cite: 2]
os.tmpname()               -> string "/tmp_<millis>"[cite: 2]
os.exit()                  -> same as os.home(), no return[cite: 2]
os.launch(name)            -> boolean (queued only, ASYNC -- see below)[cite: 2]
os.home()                  -> no return, ASYNC (see below)[cite: 2]
os.bright(0-100)           -> sets display brightness (percent), no return[cite: 2]
os.reset()                 -> ESP.restart(), does not return[cite: 2]
os.frameTime()             -> number, seconds since previous call (0.0 first call)[cite: 2]

os.launch()/os.home() are ASYNCHRONOUS: they queue the app switch for the
next tick on core0 (switching apps isn't safe from core1 where Lua runs)[cite: 2].
Code immediately after os.home() WILL still execute[cite: 2].

=====================================================================
io.open(path, mode)        -> file | nil,err   modes: r w a r+ w+ a+[cite: 2]

rely on this under heap pressure -- always call :close() explicitly)[cite: 2]

gpio.*
=====================================================================
gpio.mode(pin, mode)        -> mode: 0=INPUT 1=OUTPUT 2=INPUT_PULLUP
                                3=INPUT_PULLDOWN. Invalid mode silently
                                does nothing (no error raised).[cite: 2]
gpio.write(pin, val)        -> digitalWrite[cite: 2]
gpio.read(pin)               -> digitalRead, 0/1[cite: 2]
gpio.aread(pin)               -> analogRead[cite: 2]
gpio.awrite(pin, val)         -> analogWrite (PWM)[cite: 2]
gpio.tone(pin, freq[, duration=0]) -> tone()[cite: 2]
gpio.notone(pin)              -> noTone()[cite: 2]
(no pin range validation -- invalid/negative pin numbers are passed
straight to the underlying Arduino calls, behavior is whatever the
core does with an out-of-range pin, not a clean Lua error)[cite: 2]

=====================================================================
require / run / dofile / print / sleep / loop  (globals)[cite: 2]
=====================================================================
require(name)                  -> cached module table [see BUG-7].
                                 Searches /sd/lua/<n>.lua, /sd/<n>.lua,
                                 /<n>.lua, /sd/lib/<n>.lua in that order.
                                 Circular require raises a clear error
                                 instead of hanging.[cite: 2]
run(path)                        -> loads+executes; on error, PRINTS to
                                 terminal and returns -- does NOT raise
                                 a Lua error [see BUG-6].[cite: 2]
dofile(path)                      -> loads+executes; missing file or
                                 syntax/runtime error RAISES via
                                 lua_error/lua_call [see BUG-6].[cite: 2]
print(...)                        -> writes to the on-screen terminal[cite: 2]
sleep(ms)                          -> blocking delay[cite: 2]
loop(fn)                            -> runs fn every frame; fn returning
                                    false stops the loop[cite: 2]

=====================================================================
PATCHES IN THIS SESSION (applied in PaperOS_v1_1_patched_fixed.zip,
the reference above was written BEFORE them — updated notes)[cite: 2]
=====================================================================
- timer.every()/timer.after(): fixed UB — calling timer.every() FROM INSIDE
  a timer callback could previously invalidate the range-for iterator
  (push_back -> realloc -> dangling reference). Now safe[cite: 2].

- loop(): previously DID NOT reset g_exec.interrupt after stopping on Ctrl+C
  -> subsequent sleep()/net.get()/json.decode() calls would immediately throw a false
  "interrupted" error. The flag is now properly cleared at the end of loop()[cite: 2].

- net.scan(): converted to async WiFi.scanNetworks(true) polling every 200ms
  with Ctrl+C checking. Previously blocked core1 with no way to interrupt[cite: 2].

- gpio.mode()/gpio.write()/gpio.awrite()/gpio.tone(): now CHECK if a pin belongs
  to system hardware (keyboard, SD, display, audio/mic/IR — based on official
  Cardputer v1.1/Stamp-S3A pinmap) and throw luaL_error instead of silently
  corrupting hardware state. G1/G2 (Grove) are intentionally left unrestricted
  as they are truly free pins[cite: 2].
  Reserved pins list: 3,4,5,6,7,8,9,10,11,13,15 (keyboard),
  12,14,39,40 (SD), 33,34,35,36,37,38 (display/RGB), 41,42,43,44,46
  (audio/IR/mic)[cite: 2].

- fs.copy(src,dst): now checks each write operation and returns
  (false, "write failed (disk full?)") instead of silently returning true on
  write errors (e.g., when SD is full)[cite: 2].

- _fsExists/_fsRemove/_fsMkdir/_fsRename: now recognize uppercase "/SD"
  alongside "/sd", matching _fsOpen behavior[cite: 2].

- os.date(): buffer expanded from 64 to 128 bytes; returns "" on overflow
  instead of potential garbage data[cite: 2].

- io.stdin / io.stdout / io.stderr: now set to nil (previously dummy strings).
  Calling f:write() on them now raises a clear "attempt to index a nil value"
  error instead of a confusing "attempt to call a string value"[cite: 2].

All seven BUG-1..BUG-7 items and QUIRKs from the main text above
REMAIN RELEVANT — they were not modified in this session[cite: 2].
